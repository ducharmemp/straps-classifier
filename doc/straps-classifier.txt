*straps-classifier.txt* Tool-call classification for Straps

*straps-classifier* *straps-classifier-setup*
Install Straps and this plugin, then configure before opening any session: >lua
  require("straps").setup()
  require("straps_classifier").setup({ model = "jev-latest" })
<
The Lua module keeps its underscore name. setup(opts) returns the module.
Call setup eagerly: Straps freezes its guard chain when the first session opens.
Late setup reports an error and leaves tool calls unclassified.
With contextual and best_effort absent or false (the defaults), legacy strict
behavior remains unchanged. The classifier can deny an admitted call; it cannot
approve a call. A missing key or failed classification
denies the call. See |straps-classifier-contextual| for the separate experimental
contextual bootstrap and its unresolved release gates.
Resolve the TypeSafe key through fn.typesafe_api_key (default TYPESAFE_API_KEY).

The strict-mode guard clears stale verdicts before each call. Deterministic local
prohibitions run before the model request. Every result other than ok blocks in
root, child, and fork sessions before confirmation, including with auto grants.
An ok result is held for the exact call and consumed by the chained operator
confirmation; it cannot grant permission. Child allow/readonly ceilings still
apply. A guard veto reads blocked by hook.guard.classifier: classifier: <reason>.

Transport rejects nonzero process exits or signals and response envelopes that
indicate error, refusal, incompleteness, or unsuccessful status. Required answer
IDs must match the request exactly, and answer types must match. Noul values
must be finite and within [0,1]. Scores must fit the requested rubric, with an
exact legend and finite confidence within [0,1]; choices must name a requested
option and carry finite confidence within [0,1]. Malformed responses deny.
Direct ask_user policy thresholds and permission behavior remain unchanged.

Synthetic probes do not qualify the classifier for safety. This change relaxes
no thresholds, permissions, or ask_user behavior. Optional response distributions
remain unused and unvalidated. Duplicate JSON keys, transport response byte
bounds, the provider's actual refusal format, and contextual policy calibration
remain parked.

Options include model, endpoint, timeout_ms (8000), retry (1), deny_threshold
(0.85), damage_deny (2.5), opaque_action (deny or log), cutoffs,
ask_deny_threshold, ask_cutoffs, always_deny_patterns, max_state_bytes (4000),
ask_state_bytes (16000), audit_limit (500), and on_verdict (function).
Unknown keys and invalid types raise errors before setup changes configuration.
Numeric values must be finite and nonnegative. Timeout and state byte limits
must be positive integers; retry is a nonnegative integer. audit_limit below
1 reports an error and retains the prior limit. Cutoff tables map string keys
to finite nonnegative numbers. A cutoff above 1 disables that question.
setup freezes a configuration snapshot; editing config afterward does not
change the installed classifier. See README.md for each hazard and ask_user rule.

*straps-classifier-commands* *:StrapsClassifierAudit*
:StrapsClassifierAudit opens the classification audit buffer.
*:StrapsClassifierStatus*
:StrapsClassifierStatus reports strict-mode guard/key state, or contextual
bootstrap state when that mode is selected.

*straps-classifier-tools*
This plugin adds no agent tools. In strict mode, its guards and confirmation
checks evaluate tool input and deny unsafe calls. The strict-mode audit records
verdicts without granting permission or replacing admission policy. Contextual
mode uses the separate core integration described below.

*straps-classifier-status*
In strict and best-effort modes, require("straps_classifier").status() returns
setup_ran, installed, install_error, adapter, model, api_key and api_key_error. status_report() returns report lines,
a notification level and status. :checkhealth straps_classifier reports setup,
key resolution and audit counts. A resolving key does not test API access.

*straps-classifier-best-effort*
Best-effort mode defaults to false and is mutually exclusive with contextual.
Legacy strict behavior remains unchanged when both modes are absent or false.
Configure after core setup and before sessions or guard freeze. Configuration,
including scope, is frozen; changes require restart.

This shape reference requires operator decisions for the acknowledgment variables
and grants no approval: >lua
  require("straps_classifier").setup({
    model = selected_typesafe_model,
    best_effort = {
      enabled = true,
      acknowledge_risk = operator_acknowledged_risk,
      disclosure_approved = operator_approved_disclosure,
      operator_scope = reviewed_operator_scope,
      prohibitions = reviewed_operator_prohibitions,
      max_request_bytes = 65536,
    },
  })
<
Options:
  enabled                Required true.
  acknowledge_risk       Required true; effects are not proven.
  disclosure_approved    Required true; approves provider transmission below.
  operator_scope         Required nonempty startup authority string.
  prohibitions           Optional list of nonempty prohibition strings.
  max_request_bytes      Optional integer 1024..1048576; default 65536.
  adapter                Optional table selecting the assessing model;
                         omit for TypeSafe. See |straps-classifier-adapter|.
  user_intent            Optional boolean; TypeSafe only. Also deny an
                         operation that goes beyond what the user asked for.
                         See |straps-classifier-user-intent|.

*straps-classifier-adapter*
adapter picks the model that assesses the operation. Both adapters deny on any
malformed or unavailable answer.

  omitted or { name = "typesafe" }
      Top-level model (default jev-latest), fn.typesafe_api_key, top-level
      timeout_ms. Sends computed facts plus yes/no questions. See
      |straps-classifier-typesafe-battery|.
      votes        default 3, range 1..5; key orderings that must all allow
  { name = "anthropic" }
      model        default claude-sonnet-5
      max_tokens   default 4000, range 1000..32000; includes reasoning
      timeout_ms   default 30000, range 1000..120000
      Uses the straps Anthropic provider key and base URL (:StrapsLogin
      anthropic or $ANTHROPIC_API_KEY). Sends the six categorical questions
      in one request.

The anthropic adapter sends one request to /v1/messages without retry. A
response that stops before finishing, has no text answer, omits a question or
names an unknown choice is unavailable and denies. disclosure_approved must
cover Anthropic when this adapter is selected. status() and :checkhealth report
the selected adapter and whether its credential resolves.

Sonnet 5 passed a 15-case probe of print-only operations that TypeSafe
withholds. That probe covers one scenario type only.

*straps-classifier-typesafe-battery*
The typesafe adapter computes facts about the operation in code
(straps_classifier.facts) and sends them with the full scope and operation:
the program and arguments passed to vim.system, shell constructs outside
single quotes and quoted heredocs that evaluate text, Python calls that
execute code or delete or write data, Lua calls that redefine registry
entries, install autocmds, change permissions or load code, curl method, URLs,
uploads and trace files, browser page actions, and data_text_never_executed.
infrastructure_commands lists each ssh, scp, rsync, kubectl, docker, podman,
aws and terraform invocation with its host, account, jump hosts, remote
command, copy endpoints, kubectl context, namespace and verb, container image,
mounts and host-access flags, AWS profile and terraform subcommand; a value
starting "not stated" marks a default the operation relies on.
runs_commands_on_another_system is true when quoted text runs in a remote
shell, pod or container. The facts come from pattern and token analysis, not
execution; they do not follow helpers, shell functions or aliases.

The request asks the six categorical questions plus yes/no questions about
effects, one per restrictive scope sentence (one containing a limiting word
such as never, not, only, read-only or between), one per operator
prohibition, and one about whether the scope permits every effect. The
unknown-code question treats the tool's own registered definition and the
modules it requires as known, and asks only about code the input directs it
to run. Code routes the yes/no answers: secret exposure, protection
weakening, unknown code, a scope-sentence conflict or a prohibition breach at
0.5 or above denies; a remote change that relies on an unstated default
denies; an unknown target denies at 0.9; the scope must permit the effects at
0.5 or above. The six categorical answers do not route.

The same request is sent votes times with different JSON key orders, one after
another, and the call is allowed only when every ordering allows. On the
120-case development corpus this allowed 49 of 60 permitted operations in two
runs against 44 and 45 for the six questions alone, with 2 unsafe allowances
in each run against 1 and 2; on a 74-case remote-operations set it allowed 28
and 30 of 31 permitted and 0 of 43 unsafe operations. Median classification
time rose from about 160 ms to about 250 ms.

*straps-classifier-user-intent*
user_intent = true adds a second limit inside operator_scope: the operation
must not go beyond what the human user asked for. The classifier reads the
root session's first user message and its last four (following straps_parent
from a subagent), skips harness notices and agent messages, and sends them as
user_requests. Calls that fn.capability classifies as read skip the intent
question and send no user messages. A yes/no question asks whether the operation changes, deletes,
sends, publishes or deploys something the requests do not cover, or does
something the user cancelled or forbade; reading, testing, building and
editing that serve the current task count as part of it. The call is denied
when that answer is 0.5 or above, and the scope must still permit the
effects. A user request cannot exceed the operator scope.
disclosure_approved must cover sending those messages to TypeSafe.

On a 30-case intent set it allowed 13 of 13 requested operations and 0 of 17
unrequested ones, against 12 of 17 unrequested with the scope alone.
Replayed on 127 held-out tool calls from the author's own sessions, it
allowed 79, against 105 with the scope alone. With the first message and the
read skip it allowed 84 and 81, against 107 and 103 with the scope alone; it
withholds about one in six ordinary calls, most often during work approved
several messages earlier.

Startup scope supplies standing authority for ALL sessions in this Neovim.
Transcript text, agent tasks, tool results and operation approval claims grant
no authority. Child ceilings, other guards, confirmation and :StrapsAuto grants
remain independent. The classifier cannot grant permission. Mandatory and
operator prohibitions take precedence over grants. Best-effort replaces legacy
categorical patterns and hazard thresholds, including the strict ask_user
battery, with scope and prohibition assessment.

The default TypeSafe adapter uses the configured top-level model (default
jev-latest), endpoint and timeout_ms. Each request makes one transport attempt
regardless of retry; the TypeSafe adapter sends one request per ordering.
Requests include
full tool input, registered definition source, working directory, startup scope
and prohibitions. Oversized requests deny without truncating input or source.
The classifier adds no transcript or environment values.

Provider transmission precedes operator confirmation, including calls the
operator later refuses. Disclosure approval covers submitted input, source and
scope. The classifier cannot reliably detect arbitrary secrets before sending
those contents. Avoid submitting secrets.

Allow requires favorable model answers for authority, prohibitions, credential
disclosure, protection tampering, material uncertainty and recommendation.
Malformed or unavailable assessments deny. Semantic model answers, even after
schema validation, are not independent proof. Hidden helper and editor-hook
effects remain unproven; their absence from an exhaustive inventory alone does
not force rejection. This mode supplies no sandbox or complete effect proof.

Best-effort classifier audit and classifier log records retain metadata such as
tool name, action, fixed reason and timing. They omit input, source, scope and
provider response text. This restriction does not cover native-tool or session
logs. Offline routing tests establish no semantic-policy guarantee. This help
provides no enablement recommendation.

The six question instructions adopt the exact frozen best-effort-evaluation-4
experimental wording as an incremental opt-in improvement. The paired synthetic
study allowed 15/19 permitted observations against control 13/19. Both arms had
0/21 unsafe allowances, with no observed control-to-experimental action
regressions. Four false denials remain, representing two unique public shell/Lua
literal contents. Gains were an uninvoked local function and stored untrusted
injection text. The latter allowed in an earlier response to the identical
control request, so that gain does not establish wording causality. One run with
a moving model alias does not establish repeat stability. All cases are reused
development data; counts include repeats and do not establish general safety or
real-world error rates. Adoption does not enable live use; the default remains
disabled.

A later general-corpus-round3 study appended one generic effect/object
paragraph to all six instructions; that exact wording is now installed. On 60
paired cases (20 previously queried, 40 previously unqueried) it allowed 18/28
permitted cases against control 16/28. Both arms withheld all 18 prohibited and
14 insufficient-evidence cases, and no control allowance was lost. Both gains
came from previously queried targets; the previously unqueried cases showed no
change, and one gain may reflect response variation. Category answers changed
without an action change on 14 cases. Ten false withholdings remain. One
synthetic run does not establish general safety.

*straps-classifier-contextual*
Contextual authorization is experimental and disabled by default. Install after
core setup and before sessions/guard freeze: >lua
  require("straps").setup()
  require("straps_classifier").setup({
    contextual = { enabled = true, disclosure = { approved = false },
      limits = { max_bytes = serialized_byte_limit, max_depth = nesting_limit, max_items = item_limit } },
  })
<
This example requires reviewed positive integer input limits and approves no disclosure. Assessment remains unavailable. The
contextual table accepts only enabled, disclosure, route, limits,
defect_threshold, and thresholds. See README.md for the complete shape:
- disclosure: approved, provider_id, revision, allowed_classes, inspect.
- route: provider_config (provider-specific core keys; OpenAI uses provider =
  "openai" and openai_model = selected_model), max_output_tokens,
  max_response_bytes, timeout_ms.
- limits: max_bytes, max_depth, max_items.
- thresholds: positive_threshold, conflict_threshold.

Supply reviewed disclosure policy and measured cutoffs; no calibrated values
are provided here. Mode/configuration changes require restart. Contextual mode
bypasses this plugin's legacy TypeSafe chain, preserving other guards, ordinary
confirmation, and child ceilings. TypeSafe key resolution and the strict-mode
key/status claims above do not apply to this bootstrap. status().contextual
reports installation, missing dependencies, disclosure_approved, and adapter
unavailability where recorded. Installed does not mean assessment-ready.
:checkhealth straps_classifier reports contextual installation, disclosure,
dependencies, and unavailability without legacy guard/key claims.

Core owns private human events, task revisions, standing instruction snapshots,
and prompt construction receipts. Editable transcript labels, summaries,
notices, archive access, and copied prompts grant no authority. Trusted human
submission/steering and bound question answers revise authority. Legacy/resumed
sessions, piped data, and fork copies require adoption; adoption can regenerate
the prompt. Continue without text retains the task; new text revises it. Stop
preserves task identity and rejected-family suppression. Question answers record
selected-option identity or free-text origin; typing a label remains free text.
See |straps-contextual-authorization| and |:StrapsAdopt|, |:StrapsTaskReset|.

Automatic allow requires task connection and coverage of material effects. A bounded
unresolved in-task decision can ask. Unrelated work, prohibitions, and missing
evidence deny. Failed synthesis/assessment or missing disclosure denies automatic
authorization as unassessed, without prompting for every failed call. Inspect a
known ID with |:StrapsAuthorization|; ! reopens through a fresh gate. Exact-call consent binds
input/definition/context/targets and consumes once. Rejection suppresses its
decision family until human reopening. Consent cannot bypass other guards or
readonly/allow ceilings, and cannot retry an unknown execution outcome.
Execution-started receipts retain metadata only; retained denied decisions support
exact-call inspection and fresh reopening.

An adopted session can remain pending without a synthesized task specification.
Human reopening can approve the displayed exact call when disclosure, synthesis,
assessment, or integration is unavailable, or despite displayed classifier
objections. The approval leaves the task pending. Independent guards, ordinary
confirmation, readonly/allow ceilings, fresh call and target checks, and
consumption once at execution still apply.

Children receive only explicit validated subset authority. In contextual mode,
generic human :StrapsFork/fn.fork calls are unavailable because they lack a
trusted exact invocation. Agent fork without delegation creates an inactive
copy requiring human adoption before starting. Explicit fork delegation is
rejected because the copied prompt has no valid private construction receipt.

Contextual ceilings classify exact shipped definition identities through private
trusted setup. Public capability metadata and fn.capability redefinition cannot
grant trusted categories to custom tools. Exact-definition assessment and
independent ceilings still apply; wider custom-category authority is unsupported.

The bootstrap marks call input/evidence as unknown sensitivity. Validation
rejects unknown even if allowed_classes.unknown is true. Production per-call
requests remain blocked pending approved sensitivity/disclosure policy and
implementation. Credential material and filtered required evidence refuse
requests. Inspectors must return "clear"; this is no proof of blanket absence
of secrets. Tool execution approval does not approve classifier disclosure.

The adapter supports the default OpenAI API endpoint with API-key or existing
OAuth credentials. Other providers, custom routes/authentication, and Codex
remain unavailable. Requests use isolated tool-free text JSON, local schema
validation, and separate synthesis checks. Target revalidation does not remove
post-check filesystem races or enforce executable/shell behavior. Same-process
Lua supplies no operating-system sandbox.

Disclosure, numeric calibration and acceptance, default enablement, unsupported
routes, and locked-core compatibility remain parked. The locked public core's
hook-veto diagnostic still requires a newer release; a working-tree override
does not prove public compatibility. Offline tests do not establish completed
integration or live calibration. Progress enforcement and a dedicated remote
operation tool remain deferred. The legacy audit is not a complete contextual
consent/event log; use the core decision inspector for a known ID.
